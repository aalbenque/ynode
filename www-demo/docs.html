Introduction

YNode is a lightweight HTTP/1.1 web server written entirely in Bash. It uses socat to handle network I/O and implements the full request/response cycle in shell scripts, with pluggable module handlers for static files, FastCGI (PHP-FPM), CGI, reverse proxy, health checks, and more.

⚠️
Active development. HTTP/2 support is experimental and non-functional. See Limitations for details.

Features

⚡
Pure Bash
No compiled server binary required; runs anywhere Bash 4+ is available.
🔒
SSL / TLS
HTTPS via socat's OPENSSL-LISTEN with configurable certificates.
🐘
FastCGI / PHP-FPM
Communicates with PHP-FPM over Unix sockets; optional C helper for ~10× faster encoding.
📁
Static file serving
ETag, Last-Modified, 304, HTTP Range (206 / 416), static compression.
🔑
HTTP Basic Auth
Per-directory protection via standard htpasswd-format files.
🔌
Module system
.ynaccess files select the handler module per path, per directory.
🔁
Keep-alive
Persistent connections with configurable timeout.
👁️
File metadata cache
file_watch.sh daemon maintains ETag/MIME cache via inotifywait.
🗜️
Compression
Per-directory static_compression and dynamic_compression directives for gzip, br, zstd.
📦
Chunked requests
Transfer-Encoding: chunked uploads decoded server-side with body and chunk count limits.

Building the FastCGI Helper

The C helper encodes FastCGI parameters roughly 10× faster than the pure-Bash fallback. It is optional - the server works without it, but FastCGI performance will be degraded. The compiled binary goes to helper/helper; point YN_HELPER at it in your config. 

make              # compile helper/helper
make clean        # remove compiled binary

Quick Start

1. Generate a self-signed certificate

openssl req -x509 -newkey rsa:4096 -keyout self-cert.key -out self-cert.pem \
  -days 365 -nodes -subj "/CN=localhost"

2. Start PHP-FPM (if you need PHP support)

# Arch Linux / systemd
sudo systemctl start php-fpm
# Socket path must match YN_FCGI_URI - default: unix:/run/php-fpm/php-fpm.sock

3. Build the helper

make

4. Start the server

# HTTPS on port 6680, serving ./www-demo
./server.sh -c config/ynode.conf -s

# HTTP on a custom port with a different document root
./server.sh -c config/ynode.conf -w /var/www/html -p 8080

# Verbose output written to a log file
./server.sh -c config/ynode.conf -s -v -l /tmp/ynode.log

5. Test

curl -k https://127.0.0.1:6680/ping          # health check
curl -k https://127.0.0.1:6680/ynode.png      # static file
curl -k https://127.0.0.1:6680/index.php      # PHP via FastCGI
curl -k -u user:pass https://127.0.0.1:6680/restricted  # Basic Auth

CLI Usage

Usage: server.sh [OPTIONS]

Options:
  -h, --help              Show this help message and exit
  -v, --verbose           Enable verbose output
  -d, --debug             Enable debug output
  -l, --logfile <file>    Write log output to <file>
  -c, --config <file>     Load configuration from <file> (repeatable)
  -w, --www-root <dir>    Set the HTTP document root
  -p, --port <number>     Set the port to listen on
  -s, --ssl               Enable SSL/TLS

Multiple -c flags are sourced in order - later files override earlier ones: 

./server.sh -c config/ynode.conf -c config/site.conf -s

Request Processing Flow

server.sh
  └─ socat TCP-LISTEN / OPENSSL-LISTEN
       └─ per connection: exec http1.1.sh

http1.1.sh
  ├─ Read request line → parse method, path, query string
  ├─ Read headers (until blank line)
  ├─ Read body (Content-Length or chunked Transfer-Encoding)
  └─ Source method_call.sh

method_call.sh
  ├─ Canonicalize and validate path (path traversal prevention)
  ├─ Load .ynaccess from request directory (or default_ynaccess)
  └─ Set YN_MODULE and YN_MODULE_PARAMETERS

modules/<name>.sh
  ├─ prepare_headers()  - validate request, set response code and headers
  └─ output_content()   - write response via output_headers() + body

http1.1.sh
  ├─ Check Connection: keep-alive
  └─ Loop for next request or close

.ynaccess Routing Files

Each directory in the document root can contain a .ynaccess file - a Bash script sourced by method_call.sh for every request targeting that directory. It selects the backend module and applies per-request transformations.

Example .ynaccess

# Security headers on every response
add_header "X-Frame-Options" "DENY"
add_header "X-Content-Type-Options" "nosniff"

# Block access to .ynaccess files themselves
if match "\.ynaccess$"; then
    deny

# Health check endpoint
elif match "^/ping$"; then
    module ping

# Reverse-proxy /api/* to Node, stripping the prefix
elif match "^/api/"; then
    rewrite_prefix "/api" ""
    module proxy http://127.0.0.1:3000

# Run a legacy CGI script
elif match "^/report\.cgi$"; then
    module cgi /usr/lib/cgi-bin/report.cgi

# Directory requests → index.php via FastCGI, compressed
elif is_directory; then
    rewrite_path "${YN_R_PATH}/index.php"
    dynamic_compression gzip
    module fcgi unix:/run/php-fpm.sock

# PHP files → FastCGI, compressed
elif extension "php"; then
    dynamic_compression gzip
    module fcgi unix:/run/php-fpm.sock

# Static assets: pre-compress with brotli, cache one year
else
    add_header "Cache-Control" "max-age=31536000, public"
    static_compression br 1024
    module static
fi

Static File Caching

YNode caches static file metadata (ETag, Content-Type, Content-Length) in YN_STATIC_DATA_DIR (default: /tmp/yn-static-data-dir), avoiding repeated file, md5sum, and stat calls.

The file_watch.sh daemon uses inotifywait to monitor the document root and invalidates cache entries when files change or are deleted. The cache directory is wiped and recreated on each server start.

Request headerResponse
If-None-Match304 Not Modified (ETag comparison)
If-Modified-Since304 Not Modified
Range206 Partial Content (byte ranges)
Range (invalid)416 Range Not Satisfiable with Content-Range: bytes */N

Compression

Static compression

Pre-compress static files and serve the compressed version when the client's Accept-Encoding matches. The compressed file is generated on first request and cached in YN_STATIC_DATA_DIR alongside the ETag metadata. 

# Compress files larger than 1024 bytes with brotli
static_compression br 1024

# Or with gzip / zstd
static_compression gzip 512
static_compression zstd 2048

# Disable
static_compression off

Dynamic compression

Compress FastCGI responses on the fly. Compressible content types (text/*, application/json, application/javascript, etc.) are compressed before being sent. By default the body is buffered so an accurate Content-Length can be set. 

dynamic_compression gzip
dynamic_compression br
dynamic_compression zstd
dynamic_compression off

Forced chunked streaming for compressed responses

When buffering a dynamic response is undesirable, enable Transfer-Encoding: chunked streaming instead. This avoids holding the full response in memory at the cost of slightly higher per-chunk overhead. 

force_compressed_streaming on   # stream compressed body as chunks
force_compressed_streaming off  # buffer, set Content-Length (default)

Compression levels

Set globally in ynode.conf. Separate levels exist for static (offline, high quality) and dynamic (on-the-fly, fast):

VariableDefaultUsed for
YN_GZIP_LEVEL9Static pre-compression
YN_BROTLI_LEVEL9Static pre-compression
YN_ZSTD_LEVEL15Static pre-compression
YN_GZIP_LEVEL_OTF3Dynamic on-the-fly
YN_BROTLI_LEVEL_OTF1Dynamic on-the-fly
YN_ZSTD_LEVEL_OTF1Dynamic on-the-fly

Chunked Request Bodies

YNode decodes Transfer-Encoding: chunked request bodies server-side (file uploads, streaming clients). A request that sends both Transfer-Encoding and Content-Length is rejected with 400 Bad Request to prevent request smuggling. The decoded body length is forwarded as CONTENT_LENGTH to FastCGI and CGI backends.

VariableDefaultDescription
YN_MAX_BODY_SIZE52428800Maximum total decoded body size in bytes (50 MiB)
YN_MAX_CHUNKS8192Maximum number of chunks per request

Set these in config/ynode.conf.

HTTP Basic Authentication

Protect a path by calling auth_basic in a .ynaccess file:

if match "^/admin"; then
    auth_basic "Admin Area" "./.ynpasswd"
fi

The htpasswd file uses SHA-512 crypt format, compatible with openssl passwd -6: 

# Create a new password entry
echo "myuser:$(openssl passwd -6 'mysecret')" >> .ynpasswd

Reverse Proxy (proxy)

The proxy module forwards requests to an upstream server using socat. It handles http://, https:// (via socat OPENSSL), and unix:/path/to/socket targets.

  • Strips hop-by-hop headers (Connection, Transfer-Encoding, Upgrade, etc.) from both directions.
  • Injects X-Forwarded-For, X-Forwarded-Proto, and X-Forwarded-Host.
  • Renames the upstream Server header to X-Proxy-Server.
  • Forwards the request body if one was received.
  • Sends Connection: close upstream - persistent backend connections are not reused.
# Strip /api prefix, proxy to a local Node.js service
elif match "^/api/"; then
    rewrite_prefix "/api" ""
    module proxy http://127.0.0.1:3000

# Proxy through a Unix socket
elif match "^/wp/"; then
    rewrite_prefix "/wp" ""
    module proxy unix:/run/nginx.sock

Note: the proxy module replies with 502 Bad Gateway if the upstream is unreachable, returns an invalid status line, or times out after 5 s.

CGI Module (cgi)

The cgi module executes a binary with a clean env -i environment populated with standard CGI/1.1 variables: REQUEST_METHOD, SCRIPT_NAME, SCRIPT_FILENAME, QUERY_STRING, CONTENT_TYPE, CONTENT_LENGTH, REMOTE_ADDR, SERVER_NAME, SERVER_PORT, GATEWAY_INTERFACE, SERVER_PROTOCOL, SERVER_SOFTWARE, and all HTTP_* headers (except HTTP_PROXY to prevent Httpoxy). The request body is fed via stdin. 

elif match "^/report\.cgi$"; then
    module cgi /usr/lib/cgi-bin/report.cgi

# Run php-cgi for a specific script
elif match "^/test_cgi\.php$"; then
    module cgi php-cgi

Writing a Module

Modules are Bash scripts in modules/ that implement two functions. The module is sourced into the request handler process, giving it full access to all request variables (YN_R_PATH, YN_HTTP_METHOD, YN_QUERY_STRING, parsed headers, etc.). 

function prepare_headers() {
    # Validate the request, set the HTTP response code,
    # and declare response headers via add_header().
}

function output_content() {
    # Emit HTTP response headers (call output_headers()),
    # then write the response body to stdout.
}
